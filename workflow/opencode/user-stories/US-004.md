# User Story — US-004 — Catálogo de libros, búsqueda y filtrado

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como administrador o bibliotecario, quiero tener un CRUD completo de libros, y como usuario quiero poder buscar y filtrar el catálogo por título, autor, género y disponibilidad.

---

## Functional Description

- **Lectura pública del catálogo:** Cualquier usuario autenticado (rol `Usuario`, `Bibliotecario` o `Admin`) puede consultar el catálogo de libros paginado y con filtros por `título`, `autor`, `género` y `disponibilidad` (libros con al menos una copia disponible).
- **Detalle de un libro:** Se puede obtener la información completa de un libro por su `Id`.
- **Creación:** Admin y Bibliotecario pueden crear un libro (título, autor, ISBN, género, descripción, total de copias).
- **Edición:** Admin y Bibliotecario pueden editar los datos de un libro y la cantidad de copias.
- **Eliminación:** Admin y Bibliotecario pueden eliminar un libro.
- **Búsqueda:** El campo portátil de búsqueda busca por coincidencia en título o autor (case-insensitive).
- **Filtros combinables:** Los filtros de título, autor, género y disponibilidad se pueden combinar libremente.
- **Permisos:** las operaciones de escritura requieren `books.create`, `books.update`, `books.delete`; la lectura requiere `books.read`. Se implementa mediante políticas de autorización + `RoleClaims` sembrados.
- **Validación:** todos los comandos de escritura validados con FluentValidation antes de procesar (título/autor obligatorios, copias ≥ 0, `AvailableCopies ≤ TotalCopies`).

## Acceptance Criteria

```gherkin
Scenario: Listar catálogo paginado
Given un usuario autenticado con permiso books.read
When consulta GET /api/books con pageSize y page
Then recibe una lista paginada de libros con metadatos de paginación

Scenario: Buscar por título
Given el catálogo contiene libros
When filtra por un texto parcial en título
Then solo se devuelven los libros cuyo título coincide

Scenario: Buscar por autor
Given el catálogo contiene libros
When filtra por autor
Then solo se devuelven los libros de ese autor

Scenario: Filtrar por género
Given el catálogo contiene libros
When selecciona el género 'Ficción'
Then solo se devuelven los libros de ese género

Scenario: Filtrar por disponibilidad
Given libros con copias disponibles y sin copias disponibles
When filtra por 'disponible'
Then solo se devuelven los libros con al menos una copia disponible

Scenario: Crear libro permitido
Given un Admin/Bibliotecario con permiso books.create
When envía POST /api/books con datos válidos
Then el libro se crea con AvailableCopies = TotalCopies y responde 201

Scenario: Crear libro sin permiso
Given un usuario sin permiso books.create
When envía POST /api/books
Then responde 403

Scenario: Crear libro inválido
Given un libro sin título o con copias negativas
When se envía POST /api/books
Then responde 400 con detalles de validación

Scenario: Actualizar libro
Given un Admin/Bibliotecario con permiso books.update
When envía PUT /api/books/{id} con datos válidos
Then el libro se actualiza y responde 200

Scenario: Vistas copias menores a total
Given un libro con copias
When se intenta actualizar con availableCopies > totalCopies
Then responde 400

Scenario: Eliminar libro
Given un Admin/Bibliotecario con permiso books.delete
When envía DELETE /api/books/{id}
Then el libro se elimina y responde 204

Scenario: Eliminar libro inexistente
Given un id inexistente
When se envía DELETE /api/books/{id}
Then responde 404

Scenario: Lectura del catálogo por un Usuario
Given el usuario autenticado con rol Usuario
When consulta GET /api/books
Then puede ver el catálogo (permiso books.read) pero no ve botones de gestión
```

## Technical Plan

### Backend (.NET 10 — Clean Architecture + CQRS Dispatcher)

1. **Domain** — ya existe `Book` (Title, Author, Isbn, Genre, Description, TotalCopies, AvailableCopies, Status, CreatedAt, UpdatedAt) y `BookStatus`. Sin cambios estructurales. La disponibilidad se deriva de `AvailableCopies > 0`.

2. **Application**:
   - `Queries/Books/GetBooksQuery` → `PagedResult<BookResponse>` con `Page`, `PageSize`, `Search`, `Author`, `Genre`, `AvailableOnly` y `CorrelationId`.
   - `Queries/Books/GetBookByIdQuery` → `BookResponse`.
   - `Commands/Books/CreateBookCommand`, `UpdateBookCommand`, `DeleteBookCommand`.
   - `BookDto`: `BookResponse`, `CreateBookRequest`, `UpdateBookRequest`, `PagedResult<T>`.
   - Validators: Create/Update (Title required ≤255; Author required ≤255; ISBN ≤20; Genre ≤100; Description ≤2000; `TotalCopies >= 0`; `AvailableCopies` en [0, TotalCopies]).
3. **Infrastructure**:
   - `Handlers/Books/` — `GetBooksQueryHandler` (EF Core con `Where` de filtros, búsqueda case-insensitive título/autor, `OrderBy Title`, `Count` + `Skip/Take`, proyección a `BookResponse`) y handlers de get-by-id/create/update/delete.
   - `TokenService` — cuando el usuario tiene roles con `RoleClaims` de permisos, inclusión de claims `permission` en el JWT (via `_userManager` + `GetClaimsAsync`).
   - `DependencyInjection.AddInfrastructure()` — registrar queries handlers (`IQueryHandler<,>`) e comandos de libros.
4. **WebAPI**:
   - `BooksController` (`api/books`) delgado: `GET /` (query con filtros), `GET /{id}`, `POST /`, `PUT /{id}`, `DELETE /{id}`; con `[Authorize]` y policies por método.
   - `Program.cs`: `AddAuthorization` con `AddPolicy("books.read", ... RequireClaim("permission", "books.read"))` y así para el resto; al arrancar sembrar `RoleClaims` de libros por rol (Admin: todos; Bibliotecario: read/create/update/delete; Usuario: read); seed de un usuario Admin inicial desde env (`ADMIN_EMAIL`, `ADMIN_PASSWORD`) solo si las variables están definidas.
   - Configuración WAL / pool por defecto existente.
   - Correlación: se aprovecha Header `X-Correlation-ID` ya soportado en `BaseQuery`/`BaseCommand`.

**Frontend (React + TS + zustand + Tailwind):**
1. `types/index.ts` — `Book`, `BookResponse`, `PagedBooks`, `BookFilters`.
2. `services/books.ts` — `getBooks(filters, page, pageSize)`, `getBook(id)`, `createBook`, `updateBook`, `deleteBook`; `api.ts` extendido con `apiPut`/`apiDelete`.
3. `hooks/useBooks` (o en page) con estado de filtros y paginación.
4. `pages/CatalogPage.tsx` — búsqueda (debounce) + filtros por autor/género/disponibilidad grilla de tarjetas con título/autor/género/portada placeholder y estado de copia; paginación.
5. `pages/BooksAdminPage.tsx` — tabla CRUD (listar, crear, editar, eliminar) visible solo con los permisos de gestión (`books.create/update/delete`), con modal/form `BookFormModal`.
6. `routes/ProtectedRoute.tsx` reutilizado + `PermissionGuard` (nuevo) que redirige/oculta según `user.permissions`.
7. Rutas: `/catalogo` (protegida) para el catálogo; `/admin/books` protegida por `PermissionGuard` con `books.create/update/delete`.
8. `Header` enlaces a Catálogo y Gestión de Libros (solo si hay permisos).

**Verificación:**
- `dotnet build` (0 errores).
- `npm run build` + `lint` (0 errores).
- Smoke test con `curl`: listado paginado, filtros por título/autor/género/disponibilidad, create (201), create sin permisos (403), create inválido (400), update ok, update con `availableCopies>totalCopies` (400), delete (204), delete inexistente (404), catálogo como Usuario (200).
