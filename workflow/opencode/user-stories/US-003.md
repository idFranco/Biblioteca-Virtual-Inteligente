# User Story — US-003 — Registro de usuarios y autenticación JWT

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como visitante, quiero registrar una cuenta con nombre, email y contraseña, y como usuario registrado quiero iniciar sesión para recibir un token JWT y acceder a la SPA en React.

---

## Functional Description

- El visitante accede a `/register`, completa nombre completo, email y contraseña, y envía el formulario.
- El sistema valida los datos (nombre requerido, email con formato, contraseña mínima 8 caracteres con mayúscula, número y carácter especial o minúscula).
- El sistema crea la cuenta con rol base `Usuario` y devuelve el par de tokens (access + refresh) iniciando sesión automáticamente.
- El usuario registrado accede a `/login`, envía email y contraseña, y recibe el par de tokens.
- El access token (15 min) se envía como `Authorization: Bearer` en llamadas autenticadas; al expirar (401) la SPA lo renueva con el refresh token (7 días).
- El usuario puede cerrar sesión, lo que revoca el refresh token en el backend.
- El endpoint de logout/revoke, registro y login están limitados a 10 peticiones/minuto por IP.

---

## Acceptance Criteria

```gherkin
Scenario: Registro exitoso
Given un visitante en /register
When envía nombre completo, email y contraseña válidos
Then se crea la cuenta con rol "Usuario"
And recibe access token + refresh token
And queda autenticado en la SPA

Scenario: Registro con email duplicado
Given un email ya registrado
When se intenta registrar de nuevo
Then el API responde 409 Conflict

Scenario: Registro con contraseña débil
Given una contraseña sin mayúscula o de menos de 8 caracteres
When se envía el formulario
Then el API responde 400 con detalles de validación

Scenario: Login exitoso
Given un usuario registrado
When ingresa credenciales correctas en /login
Then recibe access token + refresh token
And es redirigido a la ruta protegida

Scenario: Login con credenciales inválidas
Given un usuario registrado
When ingresa credenciales incorrectas
Then el API responde 401 Unauthorized

Scenario: Renovación de access token
Given un usuario con access token expirado
When la SPA detecta 401 y envía el refresh token a /api/auth/refresh
Then recibe un nuevo par de tokens

Scenario: Revocación de refresh token
Given un usuario autenticado
When cierra sesión
Then el refresh token queda revocado y reutilizarlo responde 401

Scenario: Rate limiting en /api/auth
Given 11 peticiones de login en 1 minuto
When se supera el límite
Then el API responde 429 Too Many Requests
```

## Technical Plan

### Backend (.NET 10, Clean Architecture)

1. **Domain**: entidad `RefreshToken` (Id, UserId, TokenHash, CreatedAt, ExpiresAt, RevokedAt) y `DbSet` + config en `BibliotecaDbContext` (índice único sobre TokenHash, relación User 1:N con cascade).
2. **Application**:
   - Contratos: `RegisterRequest`, `LoginRequest`, `RefreshRequest`, `RevokeRequest`, `AuthUserResponse`, `AuthResponse` (accessToken, accessTokenExpiresAt, refreshToken, user).
   - Commands: `RegisterCommand`, `LoginCommand`, `RefreshCommand`, `RevokeCommand` (records sobre `BaseCommand<TResponse>`).
   - Validators FluentValidation: nombre requerido (≤ 100), email válido (≤ 256), contraseña 8–128 con mayúscula + número + (símbolo o minúscula); tokens no vacíos.
   - `ITokenService.CreateAuthResponseAsync(User)`.
   - Excepción `ResourceAlreadyExistsException` para conflictos 409.
3. **Infrastructure**:
   - `TokenHasher` (SHA-256) para almacenar refresh tokens hasheados.
   - `TokenService`: emite access token (claims sub/email/name/jti/userId/roles) con clave JWT desde config, genera refresh token criptográfico (64 bytes), lo persiste hasheado.
   - Handlers Register/Login/Refresh/Revoke con `IValidator` inyectado y `ValidateAndThrowAsync` al inicio (validación en pipeline).
   - `DependencyInjection.AddInfrastructure()` registra TokenService, Dispatcher, handlers y validators.
4. **WebAPI**:
   - `AuthController` (api/auth): register, login, refresh, revoke — delgado, solo despacha al Dispatcher; decorado con `[EnableRateLimiting("auth")]`.
   - `Program.cs`: `AddInfrastructure()`, rate limiter de ventana fija (10/min, 429), seed de roles Admin/Bibliotecario/Usuario.
   - `GlobalExceptionHandler`: añade mapeos ValidationException→400 y ResourceAlreadyExistsException→409.
   - JWT: clave desde `Jwt:Key` (placeholder `${JWT_KEY}` resuelto por variable de entorno `Jwt__Key`/secrets), issuer/audience `BibliotecaVirtual`, access 15 min, refresh 7 días.

### Frontend (React + TS + zustand)

1. `services/api.ts`: base `http://localhost:5002` (env `VITE_API_BASE_URL`), header `Authorization: Bearer`, reintento automático con refresh ante 401.
2. `services/auth.ts`: register/login/tryRefresh/logout contra `/api/auth/*`.
3. `stores/authStore.ts`: estado zustand con persistencia en sessionStorage (mitigación XSS), hidratación al arrancar.
4. `pages/LoginPage.tsx`, `pages/RegisterPage.tsx` (Tailwind, mensajes de error).
5. `routes/ProtectedRoute.tsx` y router con `/login`, `/register` públicos y el resto protegido.
6. `Header.tsx`: muestra nombre del usuario y botón cerrar sesión.
