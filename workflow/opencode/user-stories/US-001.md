# User Story — US-001 — Inicializar estructura base del repositorio

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como arquitecto de software, quiero inicializar la estructura base del repositorio del proyecto (Frontend React + TypeScript, Backend ASP.NET Core Web API en .NET 9, la configuración inicial de Entity Framework Core con SQLite y la estructura de carpetas/archivos base para los servidores MCP), para establecer la arquitectura limpia y el punto de partida del desarrollo sin implementar aún lógica de negocio.

---

## Functional Description

Esta User Story establece el esqueleto del proyecto sin implementar lógica de negocio. Se creará la infraestructura base para que los siguientes equipos puedan trabajar en paralelo:

- **Backend:** Solución .NET 9 con Clean Architecture (Domain, Application, Infrastructure, WebAPI), EF Core + SQLite configurado, Identity scaffolding, JWT setup, CORS, rate limiting y health checks. Sin controladores de negocio.
- **Frontend:** Proyecto Vite + React 18 + TypeScript con Tailwind CSS v3, shadcn/ui, Zustand y React Router v6. Sin rutas de negocio.
- **MCP Servers:** Estructura de carpetas para biblioteca-mcp y security-audit-mcp con server.py mínimo (FastMCP).
- **Database:** Directorio workflow/database/ con placeholder .gitkeep.
- **Docker:** docker-compose.yml raíz con servicios skeleton y Dockerfiles individuales.
- **CI/CD:** GitHub Actions workflow básico que valida compilación backend y frontend.

## Technical Plan

### 1. Backend — ASP.NET Core 9 + Clean Architecture

**Comandos:**
```
dotnet new sln -n BibliotecaVirtual -o workflow/backend
dotnet new webapi -n BibliotecaVirtual.WebAPI -o workflow/backend/src/WebAPI --no-openapi
dotnet new classlib -n BibliotecaVirtual.Domain -o workflow/backend/src/Domain
dotnet new classlib -n BibliotecaVirtual.Application -o workflow/backend/src/Application
dotnet new classlib -n BibliotecaVirtual.Infrastructure -o workflow/backend/src/Infrastructure
```

**Referencias entre proyectos:**
- WebAPI → Application, Infrastructure
- Application → Domain
- Infrastructure → Application, Domain

**NuGet packages:**
- Infrastructure: `Microsoft.EntityFrameworkCore.Sql`ite`
- Infrastructure: `Microsoft.AspNetCore.Identity.EntityFrameworkCore`
- Infrastructure: `Microsoft.AspNetCore.Authentication.JwtBearer`
- Infrastructure: `FluentValidation`
- WebAPI: `FluentValidation.AspNetCore`

**Archivos a crear/modificar:**
- `Domain/`: entidades base (User, Role, Book, Rental), carpetas Entities/, Enums/, ValueObjects/
- `Application/`: interfaces de repositorio, carpetas Common/, Interfaces/, Commands/, Queries/
- `Infrastructure/`: `BibliotecaDbContext`.cs`, `IdentityConfig.cs`, `JwtConfig.cs`, `Dispatcher.cs` (mediator propio), carpetas Data/, Services/
- `WebAPI/`: `Program.cs` con EF Core + Identity + JWT + CORS + Rate Limiting + Health Checks + Global Exception Handler
- `WebAPI/`: `Controllers/HealthController.cs` (solo healthcheck, sin lógica de negocio)
- `WebAPI/appsettings.json`: connection string SQLite con WAL mode y BusyTimeout=5000

### 2. Frontend — Vite + React 18 + TypeScript

npm create vite@latest workflow/frontend -- --template react-ts

## Implementation Notes

**Rework (rejected → in progress):**
- `workflow/backend/src/WebAPI/appsettings.json`: se eliminaron los keywords no soportados por Microsoft.Data.Sqlite (`Cache Size`, `Journal Mode`, `Busy Timeout`). La connection string local queda como `Data Source=../database/BibliotecaVirtual.db;Pooling=True`. En Docker se sobreescribe vía env var con ruta absoluta (sin cambios).
- `workflow/backend/src/WebAPI/Program.cs`: se añadió `ResolveLocalSqlitePath` para resolver rutas relativas a `workflow/database/` del repo (mismo lugar que en Docker) sin depender del CWD. Se registró el nuevo interceptor en `AddDbContext`.
- `workflow/backend/src/Infrastructure/Services/SqlitePragmaInterceptor.cs` (nuevo): ejecuta `PRAGMA journal_mode=WAL` y `PRAGMA busy_timeout=5000` sobre cada conexión apuerta, preservando los parámetros originalmente declarados en `appsettings.json`.
