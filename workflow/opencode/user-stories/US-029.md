# User Story — US-029 — Eliminar leak de PII/tool-repr en el estado de lectura y reforzar la auditoría de salida de Security-Audit-MCP (detección de UUID + fail-closed)

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario de la biblioteca, quiero que el chatbot no exponga información interna del sistema ni mi user_id (PII) cuando consulto mi estado de lectura («¿Cuál fue mi último libro que leí?» actualmente filtra la serialización cruda de la herramienta MCP con mi user_id), y como administrador quiero que la auditoría de Security-Audit-MCP detecte y enmascare UUIDs/PII en la salida y no degrade a fail-open cuando el auditor falla, para que ninguna respuesta al usuario filtre datos internos ni identificadores sensibles y la auditoría permanezca efectiva incluso ante fallos de infraestructura.

---

## Functional Description

**Bug reportado (context.txt — nueva conversación):**

El usuario preguntó *"Cual fue mi último libro que leí?"* y el chatbot respondió filtrando la serialización cruda de una herramienta MCP junto con el `user_id` (PII):

```
Tu estado de lectura actual es «meta=None content=[TextContent(type='text', text='{"user_id":"3acb4f67-3439-4d0d-a94e-892ddea034d7","estado":"sin_actividad"}', annotations=None, meta=None)] structured_content={...} is_error=False result_type='complete'».
```

La respuesta expone (a) el **`user_id` del usuario** (PII) y (b) **detalles internos de serialización del MCP**. Esto es una fuga de información sensible al cliente.

Otros turnos de la misma conversación demuestran que la auditoría de **entrada** funciona (el pedido de email y de información personal fueron correctamente rechazados), lo que acota el problema a la **salida** del flujo de estado de lectura.

**Causa raíz (diagnóstico confirmado en código):**

1. **Leak del estado de lectura (fuente primaria):**
   - `workflow/chatbot/app/mcp_clients/biblioteca_client.py` `get_estado_lectura` (líneas 43-62): hace `if isinstance(result, dict): return result.get("estado")`. En producción, `result` NO es un `dict` (llega como objeto `CallToolResult`/`TextContent` crudo del SDK de MCP), por lo que cae al fallback `return str(result) if result else None`, que serializa la repr cruda incluyendo el `user_id`.
   - `workflow/chatbot/app/graph/nodes/response_node.py` (intent `status`): interpola `state.reading_state` verbatim en la respuesta (`Tu estado de lectura actual es «{reading_state}»...`).
   - `ChatState.reading_state` está tipado como `str | None`, confirmando que se esperaba texto limpio y no el objeto crudo.
   - `workflow/chatbot/app/graph/nodes/load_user_state_node.py`: asigna `state.reading_state` directamente desde `get_estado_lectura` sin validar ni purificar.

2. **Security-Audit-MCP no detecta UUID/PII en la salida:**
   - `workflow/mcp/security-audit-mcp/local_audit.py`: `_SENSITIVE_PATTERNS` cubre email/token/api_key/card_number/phone/location pero **NO incluye patrón de UUID**. El `user_id` `3acb4f67-...` no coincide con ninguno.
   - `server.py` `audit_model_output`: `safe = not injection and not sensitive`. Al no detectar el UUID → `safe=True` → `_route_output` (`build_graph.py:59`) va a `record` y `sanitize_response` **nunca se ejecuta**.
   - `mask_pii` del chatbot SÍ enmascara UUIDs (`_UUID.sub("[ID]")`), pero solo se invoca si la salida se marca insegura.

3. **Fail-open en la auditoría:**
   - `workflow/chatbot/app/graph/nodes/audit_output_node.py`: `except Exception: state.sanitized = False` → si Security-Audit-MCP falla, la respuesta se envía tal cual (fail-open).
   - `workflow/chatbot/app/graph/nodes/audit_input_node.py`: `except Exception: state.blocked = False` → si falla, la entrada se procesa sin bloquear (fail-open).
   - `workflow/chatbot/app/mcp_clients/security_audit_client.py` `_as_dict`: para un resultado no parseable devuelve `{"safe": True}` (fail-open por defecto).
   - Esto contradice la intención "fail-closed"/degradación local segura documentada en `local_audit.py`.

## Acceptance Criteria

```gherkin
Scenario: Consultar estado de lectura NO filtra tool-repr ni user_id
  Given el usuario consulta "¿Cuál fue mi último libro que leí?" (intent status)
  When el chatbot construye la respuesta
  Then la respuesta contiene SOLO el estado legible (sin_actividad|en_curso|por_vencer|vencido|recien_devuelto) o un mensaje genérico
    And la respuesta NO contiene "user_id", "TextContent", "structured_content", "meta=" ni ninguna serialización cruda de MCP

Scenario: Security-Audit-MCP detecta un UUID en la salida como sensible
  Given un texto de salida que contiene un UUID (p. ej. 3acb4f67-3439-4d0d-a94e-892ddea034d7)
  When se ejecuta detect_sensitive_local (o detect_sensitive de groq_audit)
  Then devuelve un marcador de datos sensibles (p. ej. "uuid")
    And sanitize_local enmascara el UUID con "[ID]"

Scenario: auditoría de salida degrada a sanitización local ante fallo del MCP
  Given el servidor de auditoría no responde (excepción) al auditar la salida
  When el chatbot envía la respuesta
  Then state.sanitized = True
    And la respuesta pasa por sanitize_response_node (mask_pii), enmascarando UUIDs con "[ID]"
    And ninguna respuesta se envía sin al menos sanitización local

Scenario: auditoría de entrada ante fallo mantiene política bloqueante mínima
  Given el servidor de auditoría no responde (excepción) al auditar la entrada
  When el chatbot procesa el mensaje
  Then se aplica una detección local de credenciales/inyección
    And si el input contiene un patrón credential/injection conocido, state.blocked = True

Scenario: turnos de rechazo existentes no se degradan (regresión)
  Given el usuario pide "podrías facilitarme mi email" o intenta dar su user_id
  When el chatbot procesa el mensaje
  Then la respuesta NO revela el email ni acepta el user_id como autorización
```

## Technical Plan

### Part 1 — Fix del leak de estado de lectura (AI Engineer)

**`workflow/chatbot/app/mcp_clients/biblioteca_client.py` — `get_estado_lectura`:**
- Extraer `estado` de forma robusta aceptando: `dict` (actual), `str` que sea JSON válido (parse con `json.loads` → leer `estado`), o repr con `structured_content`/`content[].text` (parse del JSON embebido).
- **Nunca** retornar `str(result)` crudo. Ante cualquier forma inesperada devolver `None` (fallback seguro).
- Implementar un helper privado `_extract_estado(result) -> str | None`.

**`workflow/chatbot/app/graph/nodes/response_node.py` (intent `status`):**
- Validar que `state.reading_state` sea un valor conocido (`sin_actividad|en_curso|por_vencer|vencido|recien_devuelto`).
- Si el valor es válido, interpolar el texto legible. Si no, usar un fallback genérico (p. ej. "No pude recuperar tu estado de lectura en este momento").
- **Nunca** interpolar un repr/objeto crudo.

**Test nuevo:** `tests/test_estado_lectura_no_leak.py` — `get_estado_lectura` con resultado repr de `CallToolResult` devuelve solo el `estado` (sin `user_id`), y `response_node` con `reading_state` inválido emite fallback genérico.

### Part 2 — Reforzar Security-Audit-MCP para UUID/PII (AI Engineer / Security)

**`workflow/mcp/security-audit-mcp/local_audit.py`:**
- Añadir patrón **UUID** a `_SENSITIVE_PATTERNS` (regex `\b[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}\b`) con el marcador `"uuid"`.
- Añadir el enmascaramiento de UUID a `sanitize_local` (reemplazar por `[ID]`).

**`workflow/mcp/security-audit-mcp/groq_audit.py`:**
- Verificar que la detección de sensibles vía LLM cubre UUIDs; si no, reforzar el prompt/instrucciones para que lo trate como PII.

**Tests nuevos:** en Security-Audit-MCP, `detect_sensitive_local` detecta un UUID y `sanitize_local` lo enmascara.

### Part 3 — Fail-closed coherente de auditoría (AI Engineer)

**Decisión confirmada (failsafe):**
- **Entrada:** si el MCP de auditoría de entrada falla, aplicar una **detección local** de credenciales/inyección (reutilizando la lógica de patrones del `local_audit` cuando sea accesible, o un fallback mínimo embebido). Si el input coincide con un patrón credential/injection conocido → `state.blocked = True`. Caso contrario procesar con degradación.
- **Salida:** si el MCP de auditoría de salida falla → **forzar `state.sanitized = True`** (nunca `False`), de modo que `sanitize_response_node` ejecute `mask_pii` local (que ya enmascara UUIDs → `[ID]`). Esto garantiza que ninguna respuesta salga sin al menos sanitización local.

**`workflow/chatbot/app/mcp_clients/security_audit_client.py` — `_as_dict`:**
- No devolver `{"safe": True}` por defecto para la salida. Para un valor no parseable, devolver un marcador `{"safe": False, "degraded": True}` o lanzar una excepción para que el nodo lo trate como fallo.

**`workflow/chatbot/app/graph/nodes/audit_output_node.py`:**
- Cambiar `except Exception: state.sanitized = False` → `except Exception: state.sanitized = True` (fail-closed con degradación segura). Registrar el fallo.

**`workflow/chatbot/app/graph/nodes/audit_input_node.py`:**
- En el `except Exception`, correr una detección local de patrones credential/injection y fijar `state.blocked` en consecuencia. Registrar el fallo.

**Tests nuevos:** `tests/test_audit_fail_closed.py` — (a) si `audit_output` lanza excepción, `state.sanitized = True` y la salida pasa `mask_pii` enmascarando el UUID; (b) si `audit_input` lanza excepción ante input con patrón credential, `state.blocked = True`.
