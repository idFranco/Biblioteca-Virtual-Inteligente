# User Story — US-007 — Alinear archivos Docker con las aplicaciones

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como administrador del proyecto, quiero alinear los archivos Docker (Dockerfiles y docker-compose.yml) con las aplicaciones para que el stack completo funcione sin inconsistencias de puertos, variables de entorno y URL base de la API al ejecutar `docker compose up --build`.

---

## Functional Description

**Ámbito:** Trabajo de alineación de infraestructura exclusivamente (Dockerfiles, `docker-compose.yml`, configuración nginx y variables de entorno de despliegue). **No** se modifica ninguna regla de negocio, endpoint, contrato de API, ni comportamiento de UI. El objetivo es que `docker compose up --build` levante el stack completo (backend 5000, frontend 5173, chatbot 8000) y que los 3 módulos interoperen igual que en desarrollo local.

**Comportamiento esperado tras el fix (visible al usuario):**
- El stack arranca completo y estable: `docker compose up --build` compila las 3 imágenes sin errores y los 3 contenedores quedan running.
- La SPA es alcanzable en `http://localhost:5173`: nginx sirve la aplicación y cualquier ruta de React Router (p. ej. `/login`, `/libros`) responde 200 al refrescar la página (fallback SPA), no 404.
- Funcionan registro e inicio de sesión: el backend inicializa la base SQLite con roles/permisos y **siembra el usuario administrador** definido por `ADMIN_EMAIL`/`ADMIN_PASSWORD`; el login del admin devuelve token JWT válido (desaparece el 400/IDX10653 por key literal `${JWT_KEY}`).
- Las llamadas de la SPA llegan al backend: la URL base de la API embebida en el bundle apunta a `http://localhost:5000` (build arg `VITE_API_BASE_URL`), con CORS ya habilitado para `http://localhost:5173`.
- El chatbot responde a su health check en `http://localhost:8000` (sin cambios funcionales).

**Nota operativa:** el backend requiere credenciales de arranque; antes de `docker compose up` hay que crear `.env` copiando `.env.example` (ver README). Sin `.env`, `docker compose up` aborta con mensaje explícito (fail-fast intencional, política de cero secretos en el repositorio).

## Acceptance Criteria

```gherkin
Scenario: El stack completo se levanta con docker compose up --build
  Given un repositorio clonado con un archivo .env creado desde .env.example
  When el usuario ejecuta `docker compose up --build`
  Then los servicios backend, frontend y chatbot compilan e inician sin errores
  And los puertos expuestos son 5000 (backend), 5173 (frontend) y 8000 (chatbot)

Scenario: La SPA es alcanzable en el puerto 5173
  Given el stack está levantado vía Docker Compose
  When el usuario navega a http://localhost:5173
  Then el navegador recibe HTTP 200 con la aplicación React renderizada

Scenario: El refresco de rutas SPA no produce 404
  Given la SPA está servida por nginx en el contenedor frontend
  When el usuario navega directo a una ruta interior (p. ej. /login) y refresca la página
  Then nginx responde con el index.html (fallback SPA) y la ruta se redirige

Scenario: El login con el administrador sembrado funciona
  Given el backend arranca con ADMIN_HOST y ADMIN_PASSWORD definidos en .env
  And el contenedor backend inicializa la base y siembra roles + admin
  When el usuario inicia sesión con las credenciales del admin
  Then la API responde 200 con un token JWT válido
  And errores previos tipo 400/IDX10653 ya no ocurren

Scenario: Las llamadas de la SPA llegan al backend correcto
  Given el bundle SPA embebe la URL base http://localhost:5000
  When el usuario ejecuta login y consulta el catálogo desde el navegador
  Then las peticiones alcanzan el backend sin errores de red ni de CORS
  And el catálogo responde con datos

Scenario: El chatbot responde al health check en el stack
  Given el servicio chatbot está levantado
  When se consulta su health check en http://localhost:8000
  Then responde 200/OK sin errores

Scenario: Sin .env el compose aborta con mensaje claro
  Given no existe archivo de variables de entorno
  When el usuario ejecuta `docker compose up`
  Then el comando aborta indicando que debe definir JWT_KEY en el archivo .env
```
