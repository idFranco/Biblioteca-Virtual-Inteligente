# User Story — US-005 — Alquiler de libros con fecha límite y devolución que libera stock

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario, quiero seleccionar un libro disponible para generar un alquiler con fecha límite; y como bibliotecario, quiero registrar la devolución para cerrar el alquiler y liberar el stock en la base de datos

---

## Functional Description

- **Creación de alquiler (UC-7):** Un `Usuario` autenticado (permiso `rentals.create`) selecciona un libro disponible y genera un alquiler con fecha límite. El sistema valida: usuario autenticado, permiso `rentals.create`, libro existente, `AvailableCopies > 0`, que el usuario no tenga otro alquiler `Active` del mismo libro, y que la `DueDate` sea válida (entre hoy y máx. 30 días).
- **Stock atómico:** Al crear el alquiler se decrementa `Book.AvailableCopies` en 1 dentro de una transacción con condición `WHERE AvailableCopies > 0` (operación atómica en SQL, SQLite con WAL y `busy_timeout=5000`). Si no hay stock, responde `409 Conflict` y no se crea ningún registro.
- **Estados del alquiler:** `Active` (creado), `Returned` (devuelto), `Overdue` (devuelto después de la fecha límite). `RentalStatus` y la entidad `Rental` ya existen en el dominio.
- **Devolución (UC-9):** Solo un `Bibliotecario` o `Admin` (permiso `rentals.return`) puede registrar la devolución de un alquiler activo. Se actualiza `ReturnedAt`, el estado pasa a `Returned` (o `Overdue` si se devuelve tarde), y `Book.AvailableCopies` se incrementa en 1 (atómicamente, sin exceder `TotalCopies`). Devolver un alquiler ya devuelto resp `409`.
- **Consulta de mis alquileres (permiso `rentals.view_own`):** cualquier usuario registrado lista únicamente SUS alquileres (scope por el `userId` del claim JWT, nunca por el id enviado por el cliente).
- **Consulta admin (permiso `rentals.view_all`):** Admin/Bibliotecario listan todos los alquileres con filtros opcionales por usuario y estado.
- **Permisos:** Se agregan a los `RoleClaims` sembrados: `Admin` → `rentals.create/return/view_own/view_all`; `Bibliotecario` → `rentals.return`, `rentals.view_all`; `Usuario` → `rentals.create`, `rentals.view_own`. Se crean las policies en `Program.cs` con `RequireClaim("permission", …)`.
- **Validación:** FluentValidation antes de procesar (BookId y RentalId no vacíos, DueDate opcional con rango [hoy, hoy+30 días]).
- **Sin impacto en chatbot/MCP:** Esta historia es solo backend + frontend; los servidores MCP y el chatbot permanecen intactos (ADR-014).

## Acceptance Criteria

```gherkin
Scenario: Usuario alquila un libro disponible
  Given un usuario autenticado con permiso rentals.create
  And un libro con al menos 1 copia disponible
  When envía POST /api/rentals con bookId y dueDate válida
  Then resp 201 con status "Active" y dueDate registrada
  And AvailableCopies decrement en 1

Scenario: Alquilar un libro sin stock
  Given un libro con AvailableCopies = 0
  When un usuario intenta alquilarlo
  Then resp 409 y no se crea ningún alquiler

Scenario: Fecha límite inválida
  Given un libro disponible
  When se envía dueDate en el pasado o a más de 30 días
  Then resp 400 con errores de validación
  And no se crea ningún alquiler

Scenario: Alquiler duplicado del mismo libro por el mismo usuario
  Given un usuario con un alquiler activo del libro X
  When el usuario intenta alquilar el mismo libro X
  Then resp 409 y el número de alquileres del usuario no cambia

Scenario: Bibliotecario registra la devolución y libera stock
  Given un bibliotecario con permiso rentals.return
  And un alquiler activo (libro sin copias disponibles)
  When invoca POST /api/rentals/{id}/return
  Then el alquiler pasa a status "Returned" con returnedAt
  And AvailableCopies del libro se incrementa en 1

Scenario: Devolución de un alquiler ya devuelto
  Given un alquiler con status "Returned"
  When se intenta devolver de nuevo
  Then resp 409 y el stock no cambia

Scenario: Devolución de un alquiler vencido
  Given un alquiler activo cuya dueDate ya pasó
  When un bibliotecario registra la devolución
  Then el alquiler pasa a status "Overdue" y el stock se libera

Scenario: Usuario no puede registrar devoluciones
  Given un usuario sin permiso rentals.return
  When intenta POST /api/rentals/{id}/return
  Then resp 403 y el alquiler sigue "Active"

Scenario: Usuario consulta solo sus alquileres
  Given existen alquileres de varios usuarios
  When el usuario A consulta GET /api/rentals/mine
  Then la respuesta solo incluye los alquileres del usuario A

Scenario: Bibliotecário administra alquileres
  Given un bibliotecario con permiso rentals.view_all
  When consulta GET /api/rentals
  Then recibe el listado paginado de todos los alquileres
  And puede ver el botón de registrar devolución
```
