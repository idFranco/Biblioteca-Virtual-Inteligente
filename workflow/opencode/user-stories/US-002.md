# User Story — US-002 — Registrar riesgos en el rol de Technical Writer

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como arquitecto, quiero agregar una sección en el rol de technical-writer que registre todos los riesgos que hay, para que los riesgos técnicos detectados (warnings de seguridad, dependencias vulnerables y otros) queden registrados de forma consistente y persistente a lo largo del ciclo de vida del proyecto.

---

## Functional Description

Se agrega una sección obligatoria de **Risk Register** al rol de Technical Writer (`.opencode/roles/technical-writer/ROLE.md`). La sección establece que el rol debe registrar todos los riesgos técnicos detectados durante el ciclo de vida (vulnerabilidades de dependencias como NU1903, warnings de seguridad, deuda técnica, configuraciones no soportadas, decisiones diferidas) de forma persistente y consistente en la bitácora de iteración `workflow/opencode/ai-engineering/`, con estructura estándar por riesgo y revisión al cierre de cada iteración. Cambio exclusivamente documental del rol opencode; sin impacto en código de aplicación.

---

## Acceptance Criteria

```gherkin
Scenario: Technical Writer must register all open risks
Given the Technical Writer role documentation at .opencode/roles/technical-writer/ROLE.md
When the "Risk Register (Riesgos)" section is inspected
Then it exists and requires registering all detected risks persistently and consistently

Scenario: Risks follow a standard structure
Given a risk is registered
When the risk entry is documented in an iteration log under workflow/opencode/ai-engineering/
Then it must include severity, affected module, description and remediation action (Severidad | Módulo Afectado | Descripción | Acción de Reparación)
```
