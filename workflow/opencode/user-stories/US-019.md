# User Story — US-019 — Corregir respuestas [REDACTED] del chatbot, restaurar memoria conversacional y validar recomendaciones cruzando catálogo local con Open Library

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario de la biblioteca, quiero que el chatbot deje de responder [REDACTED] a todos mis mensajes cuando el modelo local Ollama está en ejecución (corrigiendo la auditoría/enmascaramiento que redacta indebidamente toda la salida), que conserve la memoria conversacional para mantener el contexto entre mensajes sucesivos, y que al solicitar una recomendación de libro valide y cruce los resultados entre el catálogo local (Biblioteca-MCP) y lo disponible en Open Library (Open Library MCP), para poder mantener conversaciones coherentes y recibir recomendaciones confiables verificadas en ambas fuentes.

---

## Functional Description

Se identificaron tres defectos con causa raíz confirmada en el código:

1. **Respuestas `[REDACTED]` globales.** En `workflow/mcp/security-audit-mcp/server.py`, ante CUALQUIER fallo del auditor Groq (API key ausente/inválida, cuota, red, JSON inválido), `audit_user_input`/`audit_model_output` devuelven `safe=False` con `["audit_unavailable"]` y `sanitize_text` devuelve literalmente `"[REDACTED]"`. El nodo `sanitize_response_node` del chatbot reemplaza la respuesta COMPLETA por ese texto. Resultado: si Groq no está operativo, todo mensaje produce `[REDACTED]` o bloqueo, aunque Ollama funcione perfectamente.
2. **Sin memoria conversacional.** `main.py::chat` construye un `ChatState` nuevo por request sin historial ni identificador de sesión; `ChatRequest`/`ChatResponse` no transportan `conversationId`; el frontend (`services/chat.ts`) no envía sesión; el grafo no usa checkpointer. Adicionalmente `classify_intent_node` trata TODO mensaje no clasificado como `book_query` (catch-all `len(message.strip()) > 0`), así que «hola» dispara una búsqueda de catálogo en vez de una respuesta conversacional.
3. **Recomendaciones sin validación cruzada.** Las recomendaciones provienen únicamente del catálogo local vía `listar_recomendaciones_por_genero`; Open Library solo actúa como fallback cuando un `book_query` no encuentra nada localmente. No existe verificación de los libros recomendados contra Open Library ni sugerencias externas marcadas como solicitables.

## Acceptance Criteria

```gherkin
Scenario: Auditoría degradada no redacta toda la salida
  Given el servicio de Groq no está disponible (API_KEY_GROQ inválida o red bloqueada)
    And el modelo local Ollama está en ejecución
  When el usuario envía el mensaje "hola"
  Then el chatbot responde con un texto conversacional normal
    And la respuesta NO es "[REDACTED]" ni un bloqueo genérico
    And el evento de auditoría registrado marca la degradación (fallback local)

Scenario: PII sigue enmascarándose a nivel de segmento aunque Groq caiga
  Given el servicio de Groq no está disponible
  When el usuario recibe una respuesta que contiene un correo electrónico
  Then solo el segmento del correo se sustituye por el token de enmascaramiento
    And el resto del texto permanece intacto

Scenario: Inyección real sigue bloqueada con auditoría degradada
  Given el servicio de Groq no está disponible
  When el usuario envía un mensaje con patrones claros de prompt injection o credenciales
  Then la entrada se bloquea con la respuesta segura de bloqueo

Scenario: Memoria conversacional entre turnos
  Given el usuario envía "recomiéndame un libro de fantasía" y recibe recomendaciones
  When el mismo usuario envía "cuéntame más sobre la primera" con el mismo conversationId
  Then la respuesta refleja el contexto del turno anterior (el libro recomendado)
    And los campos transitorios del turno previo (response, recommendations, blocked…) no contaminan el turno nuevo

Scenario: Aislamiento de sesiones
  Given dos conversaciones con conversationId distintos
  When cada una envía mensajes propios
  Then ninguna respuesta mezcla contexto de la otra conversación

Scenario: Recomendación validada contra ambas fuentes
  Given un usuario con preferencias/historial que produce candidatos locales
  When pide una recomendación
  Then cada libro del catálogo local se verifica contra Open Library (ISBN o título+autor)
    And los verificados se marcan con openLibraryVerified=true y su openLibraryKey
    And la respuesta distingue "en catálogo (disponible)" de "verificado en Open Library"

Scenario: Sugerencias externas solicitables cuando no hay candidatos locales
  Given un usuario sin candidatos locales para su consulta
  When pide una recomendación
  Then el chatbot propone hasta 3 títulos obtenidos de Open Library
    And se marcan con source="open_library", availableCopies=0
    And se comunica que puede solicitar una copia

Scenario: Saludo conversacional
  When el usuario envía un saludo ("hola", "buenas tardes")
  Then el intent clasificado es smalltalk
    And la respuesta saluda y ofrece ayuda sin buscar en el catálogo
```

## Technical Plan

**Fase 1 — Security-Audit-MCP (degradación segura):**
1. Nuevo `workflow/mcp/security-audit-mcp/local_audit.py`: `detect_injection_local(text) -> list[str]` (patrones: ignore previous instructions, system prompt, credenciales, DROP TABLE/SQLi, `<script>`, exfiltración de datos) y `detect_sensitive_local(text) -> list[str]` (email, JWT, tarjetas, tokens tipo API key).
2. `server.py`: en `audit_user_input`/`audit_model_output`/`detect_prompt_injection`/`detect_sensitive_data`, captura de excepción de Groq → ejecutar variante `_local`; respuesta incluye `"degraded": true`; `_register_audit_event` guarda `{"degraded": true}` en el result.
3. `sanitize_text`: excepción → `local_mask(text)` (enmascara solo segmentos detectados); nunca devuelve `[REDACTED]` global por fallo de infraestructura.

**Fase 2 — Memoria conversacional (chatbot):**
4. `app/schemas.py`: `ChatRequest.conversationId: str | None (≤64)`; `ChatResponse.conversation_id: str | None`.
5. `app/graph/state.py`: `conversation_id: str | None`, `history: list[dict[str, str]]`.
6. Nuevos nodos: `reset_turn_node` (START→reset→audit_input): pone a `None/[]` todo campo transitorio (`intent, query, catalog_matches, recommendations, enrichment, enrichment_error, action_offer, due_reminder_flag, feedback_payload, blocked, sanitized, llm_used, response, llm_messages`), poda `history` a últimas 12 y agrega `{"role":"user","content":message}`; `record_turn_node`: agrega `{"role":"assistant","content":response}` si existe (audit_output→[sanitize_response→]record_turn→END).
7. `build_graph.py`: `AsyncSqliteSaver.from_conn_string(os.environ["CHAT_MEMORY_DB_PATH"])` (fail-fast si falta la var, coherente con ADR-025) pasado a `workflow.compile(checkpointer=…)`; `main.py`: genera `conversationId` si viene vacío (`conv-{uuid}`), lo fija en state e invoca con `thread_id`.
8. `classify_intent_node.py`: `_SMALLTALK_PATTERNS` (hola/buenas/buenos días-tardes-noches/qué tal/cómo estás/gracias/adiós) evaluados ANTES de status/recommendation/book_query; catch-all mantiene book_query solo para texto restante. `route_by_state.py`: `smalltalk` → `other` (reutiliza rama response) — mapeado explícito en build_graph condicional edges.
9. `llm_response_node.py`: también actúa en `smalltalk`; prompt incluye `history` enmascarada con mask_pii; fallback heurístico de saludo/ayuda si Ollama no disponible.

**Fase 3 — Validación cruzada de recomendaciones:**
10. `external_enrichment_node.py`: para `intent == "recommendation"`: por cada candidato ≤5, verificar contra OL — ISBN presente → `ol_verify_by_isbn`; si no → `ol_search_books(f"{title} {author}", limit=1)` + comparación de título normalizada (case/acento-insensible, patrón ADR-020). Flags por item: `open_library_verified: bool | None` (None = no se pudo verificar), `open_library_key`, `source: "catalog"`. Ejecución con `asyncio.gather` + timeout heredado de OPEN_LIBRARY_TIMEOUT/reintentos (ADR-033); fallos individuales degradan a verified=None sin romper.
11. Si `recommendations` queda vacía tras internal_catalog: `ol_search_books` con género/preferencia principal del usuario (limit=3) → suggestions con `source="open_library"`, `availableCopies=0`, `reason="Verificado en Open Library · copia solicitable"`; se insertan en `state.recommendations`.
12. `availability_node.py`: filtro de disponibilidad aplica SOLO a items `source=="catalog"`; items externos pasan intactos.
13. `response_node.py`/prompt `recommendation_prompt.txt`: enumerar con etiqueta de origen («en catálogo — disponible», «verificado en Open Library — puedes solicitar copia»).
14. `app/schemas.py`: `BookRecommendation.source: str | None`, `openLibraryVerified: bool | None`.

**Fase 4 — Frontend:**
15. `services/chat.ts`: `getOrCreateConversationId()` (sessionStorage key `biblioteca.conversationId`), enviado como `conversationId`; response actualiza el id si difiere.
16. `ChatWidget.tsx`: render de badge según `source`/`available` («En catálogo» verde/ámbar por disponibilidad; «Open Library · solicitable» azul papel); tipos TS actualizados.

**Fase 5 — Config/Docker/docs/tests:**
17. `requirements.txt` += `langgraph-checkpoint-sqlite>=2.0.0` (+ `aiosqlite` transitiva); validar import `langgraph.checkpoint.sqlite.aio.AsyncSqliteSaver` compatible con langgraph>=0.2 instalado.
18. `docker-compose.yml` chatbot: `- CHAT_MEMORY_DB_PATH=${CHAT_MEMORY_DB_PATH:?Set CHAT_MEMORY_DB_PATH (e.g. /app/database/chat_memory.db)}`; `.env.example` += variable con valor standalone `./workflow/database/chat_memory.db`.
19. Tests nuevos: `workflow/mcp/security-audit-mcp/tests/test_local_fallback.py` (Groq mock caído → degraded safe/bloqueo por patrones reales/sanitize por segmentos), `workflow/chatbot/tests/test_memory.py` (misma sesión conserva contexto vía FakeGraph/checkpointer tmp_path; sesiones distintas aisladas; transitorios limpiados), ampliación de `test_recommendations.py` (cross-validation flags, sugerencias OL, availability filtra solo catálogo) y `test_graph.py` (smalltalk routing).
