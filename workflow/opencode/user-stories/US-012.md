# User Story — US-012 — Chatbot basado en LangGraph con auditoría obligatoria y recomendación personalizada

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario, quiero interactuar con un chatbot basado en LangGraph que recomiende libros según mi historial. El flujo debe ser auditado obligatoriamente por Security-Audit-MCP antes y después de procesar, e integrar herramientas de Biblioteca-MCP y Open Library MCP, para obtener recomendaciones personalizadas con garantías de seguridad sobre la entrada y la salida.

---

## Functional Description

El usuario conversa con el chatbot de la biblioteca y, en lugar de recibir una respuesta estática, obtiene **recomendaciones personalizadas de libros** calculadas a partir de su historial de lectura (alquileres), sus preferencias de género y los datos de Open Library.

Capacidades funcionales:

1. **Recomendación personalizada por historial:** el chatbot responde a «recomiéndame algo» con una lista de libros que encajan con el historial de alquileres del usuario (géneros más leídos) y sus preferencias.
2. **Recomendación por género:** el usuario puede pedir recomendaciones de un género concreto; se consulta el catálogo interno por género vía Biblioteca-MCP y se enriquece con Open Library.
3. **Preferencias:** se almacenan y consultan las preferencias de género del usuario (`obtener_preferencias` vía Biblioteca-MCP); las recomendaciones se filtran por ellas salvo que se pida otro criterio.
4. **Feedback:** el usuario puede valorar una recomendación (me gustó / no me gustó). El feedback se persiste vía `registrar_feedback` (Biblioteca-MCP, escritura) y alimenta futuras recomendaciones.
5. **Recordatorios de vencimiento:** según el estado de lectura (`por_vencer`, `vencido`), el chatbot informa de la fecha límite o de la devolución pendiente.
6. **Auditoría obligatoria:** todo input se audita con Security-Audit-MCP antes de entrar al grafo y toda respuesta se audita antes de llegar al frontend. Entrada maliciosa => respuesta de bloqueo segura.
7. **Enriquecimiento externo:** los libros recomendados se enriquecen y verifican contra Open Library vía su MCP; se comprueba disponibilidad real en el catálogo interno antes de recomendar.
8. **LLM externo con fallback:** la redacción final de la recomendación puede generarse con el LLM externo (LangChain, vía API), con enmascaramiento de PII antes de enviar el contexto y respuesta heurística de respaldo si el LLM no está disponible.

## Acceptance Criteria

```gherkin
Scenario: Recomendación personalizada por historial de lectura
Given un usuario con historial de alquileres activo
When el usuario pide una recomendación por el chatbot
Then el chatbot devuelve libros coherentes con los géneros de su historial y disponibilidad verificada

Scenario: Recomendación por género desde el catálogo interno
Given un usuario que pide recomendaciones de un género
When el chatbot consulta el catálogo interno por género vía Biblioteca-MCP
Then devuelve libros disponibles de ese género

Scenario: Registro de feedback tras una recomendación
Given un usuario que recibe una recomendación
When el usuario valora la recomendación (me gustó / no me gustó)
Then el sistema persiste el feedback vía registrar_feedback y no interrumpe la conversación

Scenario: Preferencias aplicadas a las recomendaciones
Given un usuario con preferencias de género guardadas
When el usuario pide recomendaciones sin otro criterio
Then las recomendaciones se filtran por sus preferencias

Scenario: Entrada maliciosa bloqueada y auditada
Given un intento de prompt injection en el chatbot
When Security-Audit-MCP analiza la entrada y la detecta como no segura
Then la entrada se bloquea, no se procesa en el grafo y se devuelve una respuesta de bloqueo segura

Scenario: Fallback cuando MCP no está disponible
Given Biblioteca-MCP o Open Library MCP temporalmente no disponibles
When el usuario interactúa pidiendo recomendaciones o disponibilidad
Then el chatbot responde con un mensaje amable y no colapsa

Scenario: Solo se recomiendan libros disponibles
Given un libro candidato a recomendación sin copias disponibles
When se construye la lista de recomendaciones
Then el libro se marca o excluye indicando su disponibilidad real

Scenario: Auditoría de salida y propagación de correlación
Given una interacción completa con el chatbot
When Security-Audit-MCP procesa la respuesta antes de enviarla al frontend
Then la auditoría registra el evento con el X-Correlation-ID y la respuesta llega auditada
```

## Technical Plan

### D1. Decisiones técnicas (Technical Lead)

1. **Feedback vía Biblioteca-MCP (escritura):** `registrar_feedback` es una herramienta obligatoria según `mcp-rules.md`. ADR-011 prohíbe al chatbot tocar la base de datos directamente y enruta todo el acceso de datos por MCP. Por tanto el feedback se persiste por `registrar_feedback` (Biblioteca-MCP gana capacidad de escritura **exclusivamente** para esta herramienta; `common/sqlite.py` ya dispone de `execute`). El backend es el dueño del esquema.
2. **Backend solo esquema:** se añaden las entidades `Feedback` y `UserPreference` y su mapeo en el DbContext para que `EnsureCreated` cree las tablas. **Sin endpoints REST ni handlers CQRS** en esta historia (el chatbot escribe vía MCP). **Sin seed nuevo** (las tablas parten vacías). El archivo `workflow/database/BibliotecaVirtual.db` existente debe eliminarse una vez (y solo una) para que `EnsureCreated` regenere el esquema con las tablas nuevas; el seed de catálogo es idempotente (ADR-019).
3. **LLM externo como nodo del grafo:** se añade un nodo de respuesta con LLM (LangChain, chat model compatible con OpenAI vía API) después de disponibilidad. Enmascara PII (email, nombre real, ubicación) antes de enviar contexto al proveedor (regla `chatbot-rules`). Si el LLM falla, se usa la respuesta heurística actual (`response_node`) como fallback.
4. **Topología del grafo:** se mantiene la auditoría obligatoria de entrada (primer nodo) y salida (último nodo). Se insertan los nodos `route_by_state`, `preferences_node`, `due_reminder_node`, `overdue_node`, `feedback_node`, `save_feedback_node`. La intención `recommendation` pasa por preferencias → catálogo interno (por género/historial) → enriquecimiento Open Library → disponibilidad → respuesta.

### D2. Backend (.NET 9)

- **Nuevos archivos** en `workflow/backend/src/Domain/Entities/`:
  - `Feedback.cs`: `Id (Guid)`, `UserId`, `BookId`, `Rating (int)`, `Comment (string?)`, `CreatedAt`, `UpdatedAt`.
  - `UserPreference.cs`: `Id (Guid)`, `UserId`, `Genre (string)`, `CreatedAt`, `UpdatedAt`.
- **Modificado** `workflow/backend/src/Infrastructure/.../ApplicationDbContext.cs`: `DbSet<Feedback>`, `DbSet<UserPreference>`, configuración de relaciones (User → Feedback, User → UserPreference, Book → Feedback) siguiendo el estilo de mapeo existente.
- **Nota operativa:** borrar una sola vez `workflow/database/BibliotecaVirtual.db` para regenerar el esquema. No migraciones (proyecto usa `EnsureCreated`).

### D3. Biblioteca-MCP (Python)

- **Modificado** `workflow/mcp/biblioteca-mcp/server.py` — 5 nuevas herramientas:
  - `listar_recomendaciones_por_genero(user_id) -> list[dict]` (lectura): géneros del historial + catálogo interno por género.
  - `consultar_alquileres_usuario(user_id) -> list[dict]` (lectura): historial de alquileres del usuario.
  - `consultar_libro_en_curso(user_id) -> dict | None` (lectura): alquiler activo actual.
  - `obtener_preferencias(user_id) -> list[dict]` (lectura): preferencias de género del usuario.
  - `registrar_feedback(user_id, book_id, rating, comment) -> dict` (escritura): persiste feedback (usa `execute` de `common/sqlite.py`).
- **Modificado** `workflow/mcp/biblioteca-mcp/` tests si existen; si no, añadir tests de esquema entrada/salida, resultados vacíos y base de datos no disponible.
- Se respeta el límite de escritura: `Biblioteca-MCP` solo escribe feedback; el resto sigue siendo de solo lectura.

### D4. Chatbot (FastAPI + LangGraph + LangChain)

- **Estado ampliado** (`app/graph/state.py`): `preferences`, `recommendations (list[dict])`, `due_reminder_flag`, `feedback_payload`, `llm_used (bool)`.
- **Nuevos nodos** en `app/graph/nodes/`:
  - `route_by_state_node.py`: enruta según `reading_state` (sin_actividad, en_curso, por_vencer, vencido, recien_devuelto).
  - `preferences_node.py`: carga `obtener_preferencias` y el perfil de historial.
  - `due_reminder_node.py`: informa de alquileres por vencer.
  - `overdue_node.py`: informa de alquileres vencidos.
  - `feedback_node.py`: detecta feedback en el mensaje.
  - `save_feedback_node.py`: persiste feedback vía `registrar_feedback`.
- **Nodo LLM** (`llm_response_node.py`): LangChain chat model (OpenAI-compatible) + `pii_masker` + prompts en `app/prompts/`; fallback a `response_node` heurístico.
- **Clientes MCP ampliados** (`app/mcp_clients/biblioteca_client.py`): `listar_recomendaciones_por_genero`, `consultar_alquileres_usuario`, `consultar_libro_en_curso`, `obtener_preferencias`, `registrar_feedback`.
- **Grafo** (`app/graph/build_graph.py`): insertar nodos y aristas nuevas; mantener auditoría entrada/salida y bloqueo.
- **Schemas** (`app/schemas.py`): `ChatResponse` gana `recommendations: list[BookRecommendation]`.
- **Config**: env vars `LLM_API_KEY` y `LLM_MODEL` (sin secretos hardcodeados; `chatbot-rules`/ADR-016).

### D5. Frontend (React + TypeScript)

- **Modificado** `src/services/chat.ts`: tipos `BookRecommendation` y campo `recommendations` en `ChatResponse`.
- **Modificado** `src/components/chat/ChatWidget.tsx`: renderiza tarjetas de recomendación (shadcn/ui `Card`, portada vía `covers.openlibrary.org` con fallback ornamental existente, badge de disponibilidad, texto de razón) con la identidad visual cálida existente.
- **Affordance de feedback:** botones «Me gustó» / «No me gustó» en cada tarjeta que envían un mensaje de seguimiento al chatbot (el frontend nunca llama MCP directamente, ADR-007); el chatbot lo persiste vía `registrar_feedback`.
- **Modificado** `src/stores/chatWidgetStore.ts`: soporte de recomendaciones por mensaje.
