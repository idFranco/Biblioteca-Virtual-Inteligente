# User Story — US-017 — Resolver conflicto de puerto 11434 usando Ollama nativo del host

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como administrador del proyecto, quiero eliminar el servicio ollama del docker-compose y apuntar el chatbot al Ollama nativo del host vía host.docker.internal:host-gateway (con OLLAMA_HOST=0.0.0.0 en systemd), para que docker compose up --build funcione sin conflicto de puertos, sin duplicar el modelo llama3.2 ni duplicar consumo de RAM/GPU.

---

## Functional Description

El despliegue con `docker compose up --build` falla porque el servicio `ollama` del compose publica el puerto host `11434`, ocupado por el **servicio systemd nativo de Ollama** del equipo de desarrollo (`ollama.service`, bind por defecto en `127.0.0.1`). La historia elimina la topología "Ollama en contenedor" y adopta la alternativa ya prevista en US-016/ADR-029: el chatbot consume el **Ollama nativo del host** vía `host.docker.internal` resuelto con `extra_hosts: ["host.docker.internal:host-gateway"]`.

Como el Ollama nativo escucha solo en loopback (inaccesible desde contenedores), se requiere un cambio de sistema fuera del repo: exponerlo en `0.0.0.0` mediante drop-in de systemd (`OLLAMA_HOST=0.0.0.0`) y reiniciar el servicio.

### Comportamiento esperado

1. **Compose sin servicio ollama.** Se eliminan el bloque del servicio `ollama`, el volumen `ollama_data` y la dependencia `depends_on: ollama` del chatbot. Ningún contenedor publica `11434`.
2. **Chatbot apuntando al Ollama nativo.** El chatbot recibe `OLLAMA_BASE_URL=http://host.docker.internal:11434/v1` (desde `.env`) y `extra_hosts: ["host.docker.internal:host-gateway"]`; `OLLAMA_MODEL=llama3.2` y `LLM_TIMEOUT_SECONDS=120` se mantienen.
3. **Ollama nativo accesible desde contenedores.** El override de systemd deja a Ollama escuchando en todas las interfaces; el modelo `llama3.2` ya descargado en el host se reutiliza (sin re-descarga ni doble consumo de RAM/GPU).
4. **Cero cambios de código.** `app/llm/client.py`, el grafo LangGraph, la auditoría Security-Audit-MCP (GROQ), el PII masking y el fallback heurístico permanecen intactos: solo cambia dónde apunta `OLLAMA_BASE_URL`.

> **Ajuste por hallazgo en implementación:** con Docker Desktop no se requiere el cambio de systemd (su proxy alcanza el loopback del host); queda documentado como requisito solo para Docker Engine nativo.

```gherkin
  And ningún contenedor intenta publicar el puerto 11434

Scenario: Recomendaciones servidas por el Ollama nativo
  Given el chatbot con OLLAMA_BASE_URL=http://host.docker.internal:11434/v1 y OLLAMA_MODEL=llama3.2

  When el usuario pide una recomendación al chatbot
  Then la redacción final proviene del nodo llm_response contra el Ollama nativo
  And la respuesta conserva auditoría Security-Audit-MCP y PII masking

Scenario: Fallback heurístico preservado si Ollama nativo cae
  Given el servicio nativo ollama detenido
  When el usuario pide una recomendación al chatbot
  Then el chatbot responde 200 con el fallback heurístico sin colapsar
```

## Technical Plan

### 1. `docker-compose.yml`
- Eliminar el bloque completo del servicio `ollama` (imagen `ollama/ollama`, `ports: "11434:11434"`, volumen, entrypoint/command de pull, env `OLLAMA_MODEL`).
- Chatbot: eliminar `- ollama` de `depends_on`; agregar:
  ```yaml
      extra_hosts:
        - "host.docker.internal:host-gateway"
  ```
- Sección `volumes`: eliminar `ollama_data`.

### 2. `.env` (raíz, no versionado)
- `OLLAMA_BASE_URL=http://host.docker.internal:11434/v1` (antes `http://ollama:11434/v1`). Resto sin cambios.

### 3. `.env.example`
- Grupo Ollama: default `http://host.docker.internal:11434/v1` + comentario de topología host y requisito `OLLAMA_HOST=0.0.0.0` (systemd).

### 4. Sistema host (condicional — fuera del repo)
- Solo Docker Engine nativo: `/etc/systemd/system/ollama.service.d/override.conf`: añadir bajo `[Service]` → `Environment="OLLAMA_HOST=0.0.0.0"`; luego `sudo systemctl daemon-reload && sudo systemctl restart ollama`. Verificación: `ss -ltnp \| grep 11434` → `0.0.0.0:11434`.
- Docker Desktop: sin pasos (validado empíricamente).

### 5. Documentación
- `workflow/chatbot/README.md` (sección "LLM local Ollama"): nueva URL base host, matices Docker Desktop/Engine, nota de eliminación del servicio compose.
- `.opencode/memory/DECISIONS.md`: nuevo **ADR-032** (Ollama nativo del host como proveedor bajo compose; topología contenedor de ADR-029 deprecada); mirror en `codebase-memory_manage_adr`.
- README raíz: sin cambios (la mención genérica del LLM local sigue válida).

### Sin cambios
- Código Python/C#/TypeScript, tests, Dockerfiles, CI (`.github/workflows/ci.yml`).
