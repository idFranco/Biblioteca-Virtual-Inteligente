# User Story — US-030 — Corregir leak de repr raw de CallToolResult en el chatbot y reforzar la extracción de resultados MCP

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario de la biblioteca, quiero que el chatbot no exponga la representación interna de objetos MCP (meta=None content=[TextContent(...)]) cuando interactúo con él, y que el cliente MCP parsee correctamente los resultados usando structured_content cuando está disponible, para que las conversaciones sean fluidas y sin fugas de implementación.

---

## Functional Description

Al escribir "hola" el chatbot devolvía al usuario la serialización cruda de un
objeto MCP `CallToolResult` (`meta=None content=[TextContent(...)]`) en lugar de
una respuesta conversacional limpia.

La causa raíz está en dos capas:
1. `_parse_result()` en `app/mcp_clients/stdio.py` tenía un `except
   AttributeError: return result` que devolvía el objeto `CallToolResult` sin
   parsear cuando la extracción de texto fallaba, en lugar de usar el campo
   `structured_content` (que ya es un dict parseado) o lanzar.
2. `sanitize_text()` en `app/mcp_clients/security_audit_client.py` caía en
   `return str(result)` cuando `result` no era un `dict`, exponiendo el repr.

El fix prioriza `structured_content` (dict ya parseado por el SDK), luego el
parseo JSON del texto, y nunca devuelve el objeto MCP crudo: si la extracción
falla, se lanza para que el llamador aplique su fallback.

---

## Acceptance Criteria

```gherkin
Scenario: El chatbot responde texto limpio al saludar
Given el usuario envía "hola"
When el grafo audita la salida y el parseo del resultado MCP extrae safe_text
Then la respuesta es texto conversacional limpio, sin "meta=" ni "TextContent"

Scenario: El parseo MCP usa structured_content cuando está disponible
Given una respuesta MCP con structured_content definido
When se invoca _parse_result
Then se devuelve el dict structured_content

Scenario: Nunca se expone la serialización cruda de un objeto MCP
Given una respuesta MCP inesperada
When se invoca _parse_result o sanitize_text
Then no se devuelve el repr del objeto, sino el texto seguro o el input original
```

## Technical Plan

1. `workflow/chatbot/app/mcp_clients/stdio.py` — `_parse_result()`: priorizar
   `structured_content` (dict ya parseado), luego parsear JSON del texto, y
   eliminar el `except AttributeError: return result`. Un resultado inesperado
   ahora lanza (los llamadores ya tienen try/except).
2. `workflow/chatbot/app/mcp_clients/security_audit_client.py` — añadir
   `_safe_text()` siguiendo el patrón `_extract_estado` de US-029 y que
   `sanitize_text()` nunca serialice un objeto MCP crudo (fallback al input).
3. `workflow/chatbot/tests/test_stdio.py` — tests de `_parse_result` con un
   doble de `CallToolResult`.
4. `workflow/chatbot/tests/test_security_client.py` — tests de `_safe_text` y
   `sanitize_text`.
