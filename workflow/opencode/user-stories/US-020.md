# User Story — US-020 — Resolver pendientes post-E2E: contrato userId (case), modelo de auditoría GROQ, clasificación smalltalk, limpieza de datos de prueba y propagación de configuración a CI/Docker/docs

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como administrador del proyecto, quiero resolver los 5 pendientes detectados tras la validación de runtime E2E — (1) fijar el contrato del userId frontend↔chatbot para que la recomendación personalizada funcione con cualquier case (SQLite compara UserId case-sensitive), (2) fijar el modelo definitivo de auditoría de Security-Audit-MCP en GROQ (openai/gpt-oss-20b vs 120b) sin reintroducir degradación redactora, (3) mejorar la clasificación de smalltalk para que saludos/despedidas/agradecimientos respondan de forma cortés y breve sin derivar a recomendaciones inventadas, (4) limpiar el residuo de datos de prueba en las bases SQLite runtime conservando los datos demo de semilla y el admin, y (5) propagar el GROQ_MODEL y el contrato de userId a docker-compose, Dockerfiles, pipeline GitHub Actions y la documentación (READMEs y decisiones), para dejar el sistema consistente, configurable y sin deuda técnica post-validación.

---

## Functional Description

Resolver 5 pendientes detectados tras la validación de runtime E2E del sistema:

1. **Contrato `userId` frontend↔chatbot (case-sensitive).** La recomendación personalizada devuelve 0 cuando el `userId` enviado difiere en case del valor almacenado. SQLite guarda `AspNetUsers.Id` en MAYÚSCULAS (`93C1CA75-...`) y compara `UserId` con colación case-sensitive, mientras el JWT emite el GUID en minúsculas (`user.Id.ToString()`). El frontend ya envía el `userId` exacto del claim JWT de forma verbatim (sin transformación); el fallo está en la comparación case-sensitive de Biblioteca-MCP. Solución: normalizar la comparación con `UPPER(UserId) = UPPER(?)` en todas las queries de Biblioteca-MCP (punto único de control) y normalizar a minúsculas el INSERT de `registrar_feedback`. Documentar el contrato (frontend envía el claim `sub` verbatim).

2. **Modelo de auditoría GROQ definitivo.** Fijar `openai/gpt-oss-20b` como `GROQ_MODEL` final (ya verificado con `degraded:false` en la re-ejecución E2E), corregir el default obsoleto en `groq_audit.py` (línea 32: `llama-3.3-70b-versatile` → `openai/gpt-oss-20b`) y documentar el fallback determinista local (`degraded:true`, nunca `[REDACTED]` global).

3. **Clasificación de smalltalk (AC#8).** El mensaje "gracias, que tengas un buen día" se clasifica correctamente como `other`/smalltalk pero `llm_response_node` reutiliza el prompt de recomendaciones, por lo que el LLM deriva a recomendaciones inventadas. Solución: prompt dedicado `smalltalk_prompt.txt` + `generate_smalltalk()` usado solo para `intent == "other"`, dejando intacta la clasificación y la auditoría (sin regresión US-019).

4. **Limpieza de residuo de datos E2E en SQLite runtime.** Eliminar de forma quirúrgica e idempotente al usuario de prueba `usuario.e2e@test.local` (`93C1CA75-...`) y sus hijos (alquileres, book-request, notificaciones, refresh tokens, claims/roles) y limpiar `audit.db` de filas `e2e-*`/`test-*`. NO borrar datos demo (50 libros) ni al admin. Gate de aprobación humana antes de cualquier DELETE destructivo; backups previos.

5. **Propagación de configuración a CI/Docker/docs.** Reflejar `GROQ_MODEL` y el contrato `userId` en `docker-compose.yml` (entradas explícitas con `:?`), Dockerfiles (solo runtime, sin secretos), pipeline GitHub Actions (añadir tests de security-audit-mcp + env) y documentación (2 ADR nuevos, READMEs), sin versionar secretos.

## Technical Plan

### Item 1 — Contrato userId (case-insensitive)
- `workflow/mcp/biblioteca-mcp/server.py`: en las queries que filtran por `UserId` (líneas ~102, 155, 190, 221, 249, 254) cambiar `WHERE UserId = ?` / `WHERE r.UserId = ?` por `WHERE UPPER(UserId) = UPPER(?)` / `WHERE UPPER(r.UserId) = UPPER(?)`. En `registrar_feedback` (INSERT, línea ~324) insertar `user_id.lower()`.
- Frontend: extraer `getChatUserId()` en `workflow/frontend/src/services/chat.ts` (devuelve `useAuthStore.getState().user?.id`, verbatim, null sin sesión) y documentar el contrato en `types/index.ts` y `workflow/frontend/README.md`. NO transformar case en el frontend.
- Tests: `workflow/mcp/biblioteca-mcp/tests/test_recommendations.py` con caso case-mismatch (seed `UserId='USER-1'`, query `'user-1'` → resultados).

### Item 2 — Modelo GROQ final
- `workflow/mcp/security-audit-mcp/groq_audit.py:32`: `GROQ_MODEL = os.getenv("GROQ_MODEL", "openai/gpt-oss-20b")`.
- `.env` ya tiene `GROQ_MODEL=openai/gpt-oss-20b`; `.env.example` idem (verificado).
- Documentar fallback local (`degraded:true`, `local_audit.py`) — sin cambios de lógica.

### Item 3 — Smalltalk
- Nuevo `workflow/chatbot/app/prompts/smalltalk_prompt.txt` (respuesta breve/cortés, prohibe recomendar libros o inventar datos).
- `workflow/chatbot/app/prompts/__init__.py`: `load_smalltalk_prompt()`.
- `workflow/chatbot/app/llm/client.py`: `generate_smalltalk()` (mismo enrutado de proveedor + PII masking + `None` on failure).
- `workflow/chatbot/app/graph/nodes/llm_response_node.py`: para `intent == "other"` usar `generate_smalltalk`; mantener `_greeting_fallback()` cuando el LLM devuelve `None`. NO tocar `classify_intent_node.py` ni la ruta de auditoría (sin regresión US-019).

### Item 4 — Limpieza de datos
- `cleanup_biblioteca.sql` (delete por Guid `93C1CA75-...`: Notifications, Rentals, BookRequests, RefreshTokens, UserPreferences, Feedbacks, AspNetUserRoles/Claims/Logins/Tokens, AspNetUsers) y `cleanup_audit.sql` (`DELETE WHERE correlation_id LIKE 'e2e-%' OR 'test-%'`).
- GATE humano de aprobación antes de ejecutar; backups (`cp` a /tmp) previos; idempotente; `PRAGMA foreign_keys=ON` + `foreign_key_check`.
- Verificación: Books==50, solo admin, stock E2E restaurado. **Confirmar** el stock de 3 libros (Matar a un ruiseñor 2/0, El señor de los anillos 5/3, Orgullo y prejuicio 2/1) contra `seed-books.json` antes de restaurar nada.

### Item 5 — Propagación
- `docker-compose.yml` servicio chatbot: añadir `GROQ_MODEL=${GROQ_MODEL:?...}` y `GROQ_TIMEOUT_SECONDS=${GROQ_TIMEOUT_SECONDS:?}`; corregir `NOTIFICATIONS_CHECK_INTERVAL_SECONDS` → `Notifications__CheckIntervalSeconds` en el servicio backend.
- Dockerfiles: sin cambios (config runtime); actualizar la tabla de env de chatbot en los Dockerfiles.
- `.github/workflows/ci.yml`: añadir env `GROQ_MODEL`/`GROQ_TIMEOUT_SECONDS` al job python y el paso `python -m pytest tests` en `workflow/mcp/security-audit-mcp`.
- Docs: ADR-036 y ADR-037; READMEs (chatbot, mcp, frontend, raíz); inicializar `manage_adr`.
