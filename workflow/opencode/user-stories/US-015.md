# User Story — US-015 — Fix CI/CD: definir VITE_API_BASE_URL y VITE_CHATBOT_API_BASE_URL en el job frontend del workflow GitHub Actions y agregar al proceso las aplicaciones faltantes

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como administrador del proyecto, quiero corregir el pipeline de CI/CD de GitHub Actions para que (1) el job frontend defina las variables de entorno requeridas VITE_API_BASE_URL y VITE_CHATBOT_API_BASE_URL al ejecutar npm run build (falta provocada por el fail-fast de US-014), y (2) el pipeline cubra también las aplicaciones que hoy no se validan (chatbot FastAPI y servidores MCP con sus tests), para que el CI refleje el estado real de todo el stack y no falle en main ni en PRs.

---

## Functional Description

El pipeline de CI/CD actual (`.github/workflows/ci.yml`) tiene dos jobs: `backend` y `frontend`.

**Problema 1 — Frontend roto en CI:** el job `frontend` ejecuta `npm run build` sin definir `VITE_API_BASE_URL` ni `VITE_CHATBOT_API_BASE_URL`. La US-014 (Validated) introdujo fail-fast en `workflow/frontend/vite.config.ts` (vía `loadEnv` + `requiredEnvVars`): si esas variables faltan, el build lanza `Error: Faltan variables de entorno requeridas para compilar el frontend: VITE_API_BASE_URL, VITE_CHATBOT_API_BASE_URL` y aborta con exit code 1. Evidencia en `Error_CICD.txt` (runner de GitHub Actions, `failed to load config from .../vite.config.ts`).

**Problema 2 — Stack incompleto en CI:** el pipeline solo valida backend y frontend. El chatbot (Python FastAPI + LangGraph) y los servidores MCP (Biblioteca-MCP, Security-Audit-MCP, Open Library MCP) no tienen ningún job, aunque disponen de suites pytest autocontenidas (sin red ni secretos): `workflow/chatbot/tests` (40 tests) y `workflow/mcp/biblioteca-mcp/tests` + `workflow/mcp/open-library-mcp/tests` (25 tests). Los tests de seguridad y auditoría se cubren con fixtures `monkeypatch.setenv` y `httpx.MockTransport`; no requieren `LLM_API_KEY` ni credenciales reales.

Resultado esperado: el CI pasa en `main` y en PRs, validando backend, frontend, chatbot y MCP, respetando la política fail-fast de ADR-025 (los valores se inyectan en el workflow, no se commitan defaults).

## Technical Plan

### D1. Decisiones técnicas (Technical Lead)

1. **Sin cambios de código de aplicación:** la US-015 toca exclusivamente `.github/workflows/ci.yml` (y documentación). No se modifica `vite.config.ts` ni el código fail-fast de US-014 (política ADR-025 se conserva).
2. **Variables inyectadas en el workflow, no commitadas:** el job `frontend` define un bloque `env:` con los dos valores requeridos. Son valores de build-time de CI (no secretos) coherentes con los endpoints dev (`http://localhost:5000` backend, `http://localhost:8000` chatbot). No se crea `.env` en el repo (violaría ADR-025).
3. **Un solo job `python`:** instala dependencias de chatbot + los tres MCP e invoca pytest sobre los directorios que contienen tests. Los tests ya son autocontenidos (fixtures `monkeypatch.setenv` para `DATABASE_PATH`/`AUDIT_DATABASE_PATH`, `httpx.MockTransport` sin red), por lo que no se requieren variables ni secretos en CI.
4. **Job backend:** se mantiene `dotnet restore` + `dotnet build --no-restore --configuration Release`. No existen proyectos de test en `workflow/backend` (verificado: `find workflow/backend -iname '*test*'` sin resultados), por lo que el paso `dotnet test --no-build --configuration Release || true` es inoperante; se recomienda **eliminarlo** para evitar un falso verde silencioso. Si se añaden tests en el futuro, se reintroduce.
5. **ADR-028:** nueva decisión «CI coverage de todo el stack con config fail-fast» en `DECISIONS.md`.

### D2. Workflow GitHub Actions (`.github/workflows/ci.yml`)

**Job `frontend` — modificar:**

```yaml
frontend:
  runs-on: ubuntu-latest
  defaults:
    run:
      working-directory: workflow/frontend
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-node@v4
      with:
        node-version: '22'
        cache: 'npm'
        cache-dependency-path: workflow/frontend/package-lock.json
    - run: npm ci
    - run: npm run build
      env:
        VITE_API_BASE_URL: http://localhost:5000
        VITE_CHATBOT_API_BASE_URL: http://localhost:8000
```

*(Se añade el bloque `env:` al paso `npm run build`. Opcional: paso adicional `npm run lint` — `oxlint` devuelve exit 0 con warnings, no rompe CI.)*

**Job `backend` — modificar:**

```yaml
backend:
  runs-on: ubuntu-latest
  defaults:
    run:
      working-directory: workflow/backend
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-dotnet@v4
      with:
        dotnet-version: '9.0.x'
    - run: dotnet restore
    - run: dotnet build --no-restore --configuration Release
```

*(Se elimina `dotnet test --no-build --configuration Release || true` — no hay proyectos de test.)*

**Job `python` — nuevo:**

```yaml
python:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-python@v5
      with:
        python-version: '3.12'
    - run: pip install -r workflow/chatbot/requirements.txt
    - run: pip install -r workflow/mcp/biblioteca-mcp/requirements.txt
    - run: pip install -r workflow/mcp/open-library-mcp/requirements.txt
    - run: pip install -r workflow/mcp/security-audit-mcp/requirements.txt
    - run: python -m pytest workflow/chatbot/tests workflow/mcp/biblioteca-mcp/tests workflow/mcp/open-library-mcp/tests
```

*(Nota: no se ejecuta pytest sobre `workflow/mcp/security-audit-mcp` porque no existe directorio `tests`; sus dependencias se instalan por completitud del entorno.)*

**Validación:** `docker compose config` no aplica (no toca compose); validación YAML del workflow; build/pytest locales con los mismos comandos.
