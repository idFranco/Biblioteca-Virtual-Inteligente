# User Story — US-028 — Corregir saludos duplicados y despedidas prematuras del chatbot y limpiar/crear documentación README

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario de la biblioteca, quiero que el chatbot no salude de nuevo cuando ya estamos en medio de una conversación y que no uses frases de despedida como "¡Espero verte pronto!" cuando yo no me he despido, para que la conversación fluya de forma natural y no se sienta desconectada. Además, como administrador del proyecto, quiero limpiar la documentación README (eliminar las secciones de Tests de chatbot/backend/MCP y las notas de versiones recientes del README raíz) y crear un README para la carpeta `workflow/database`, para mantener una documentación concisa y modular.

---

## Functional Description

**Bug reportado (context.txt):** usuario en una conversación activa:
- Turno 2: "quisiera que me aconsejes" → chatbot responde con "¡Espero verte pronto!" (despedida prematura)
- Turno 3: "me gustarías que me recomiendes título..." → chatbot saluda "¡Hola de nuevo!" y cierra con "¡Espero verte pronto!" (saludo duplicado + despedida prematura)

**Causa raíz (diagnóstico confirmado en código):**

1. **Saludo duplicado ("¡Hola de nuevo!"):**
   - `llm_response_node.py:61-62`: para `intent=="other"` llama a `generate_smalltalk(message)` pasando SOLO el mensaje actual
   - `client.py:155-177`: `generate_smalltalk(user_message)` no recibe historial conversacional
   - El LLM no sabe que ya saludó → vuelve a saludar

2. **Despedida prematura ("¡Espero verte pronto!"):**
   - `smalltalk_prompt.txt:11-12`: la Regla 4 dice "Si el usuario se despide o agradece, despídete amablemente e invítale a volver"
   - La regla NO prohíbe explícitamente usar frases de despedida cuando el usuario NO se despide
   - El LLM agrega "¡Espero verte pronto!" como frase de cortesía aunque el usuario siga conversando

3. **Mismo problema en prompts de guidance y recommendation:**
   - `guide_prompt.txt`: no prohíbe frases de despedida
   - `recommendation_prompt.txt`: no prohíbe frases de despedida

**Solución de alto nivel:**
1. Agregar regla explícita en `smalltalk_prompt.txt`: "NO saludes de nuevo si el historial ya contiene intercambios previos"
2. Agregar regla explícita en `smalltalk_prompt.txt`: "NO uses frases de despedida a menos que el usuario se despida explícitamente"
3. Agregar reglas equivalentes en `guide_prompt.txt` y `recommendation_prompt.txt`
4. Modificar `generate_smalltalk()` para recibir historial conversacional y pasarlo al LLM
5. Agregar tests que verifiquen el comportamiento esperado

## Acceptance Criteria

```gherkin
Scenario: Saludo en medio de conversación NO genera "hola de nuevo"
  Given el chatbot ya saludó en un turno anterior
  When el usuario envía un mensaje nuevo (no es un saludo inicial)
  Then la respuesta NO contiene "hola de nuevo" ni otros saludos repetidos
    And el tono es conversacional y coherente con el turno anterior

Scenario: Respuesta de recomendación NO contiene frases de despedida
  Given el usuario pide una recomendación de libros
  When el chatbot responde con recomendaciones
  Then la respuesta NO contiene "¡Espero verte pronto!", "¡Hasta pronto!", "Que tengas un excelente día"
    And la respuesta termina con una pregunta o invitación a continuar (no con despedida)

Scenario: Respuesta de guidance NO contiene frases de despedida
  Given el usuario pide orientación como lector principiante
  When el chatbot responde con guía
    Then la respuesta NO contiene frases de despedida
    And el hilo conversacional queda abierto para seguir preguntando

Scenario: Despedida explícita sigue generando cierre cortés
  Given el usuario envía "adiós", "chao", "gracias, hasta pronto"
  When el chatbot procesa el mensaje
  Then responde con una despedida cortés invitando a volver
    And la respuesta SÍ contiene frases de despedida apropiadas

Scenario: Historial conversacional se pasa al LLM para smalltalk
  Given una conversación con varios turnos previos
  When el chatbot procesa un mensaje clasificado como smalltalk
  Then el LLM recibe el historial enmascarado como contexto
    And puede generar respuestas coherentes sin repetir saludos
```

## Technical Plan

### Diagnóstico

La causa raíz de los problemas es doble:

1. **`generate_smalltalk()` no recibe historial:** la función solo recibe `user_message` (el mensaje actual), no el historial conversacional. El LLM no puede distinguir entre "primer saludo" y "saludo en medio de conversación".

2. **Los prompts no prohíben explícitamente las frases de despedida:** aunque la Regla 4 de `smalltalk_prompt.txt` indica cuándo despedirse, no hay regla que diga "NO te despidas si el usuario no se despide". El LLM agrega frases de cortesía como "¡Espero verte pronto!" sin que haya una regla que lo impida.

### Cambios propuestos

**1. Actualizar `workflow/chatbot/app/prompts/smalltalk_prompt.txt`**
- Agregar regla: "NO saludes de nuevo si el historial conversacional ya contiene intercambios previos. Si el usuario ya interactuó, continúa la conversación sin repetir el saludo inicial."
- Agregar regla: "NO uses frases de despedida como '¡Espero verte pronto!', '¡Hasta pronto!', 'Que tengas un excelente día', 'vuelve cuando quieras' a menos que el usuario se despida explícitamente. Si el usuario no se despide, mantén el hilo conversacional ABIERTO."

**2. Actualizar `workflow/chatbot/app/prompts/guide_prompt.txt`**
- Agregar regla: "NO cierres la respuesta con frases de despedida. El usuario puede continuar la conversación preguntando por más detalles."

**3. Actualizar `workflow/chatbot/app/prompts/recommendation_prompt.txt`**
- Agregar regla: "NO cierres la respuesta con frases de despedida. El usuario puede preguntar por más detalles de los libros recomendados."

**4. Modificar `workflow/chatbot/app/llm/client.py`**
- Actualizar `generate_smalltalk()` para recibir parámetro `history_text: str = ""`
- Inyectar el historial en el contexto del prompt cuando esté disponible

**5. Modificar `workflow/chatbot/app/graph/nodes/llm_response_node.py`**
- En el caso `intent == "other"`, pasar `_history_window(state)` a `generate_smalltalk()`

**6. Tests nuevos en `workflow/chatbot/tests/`**
- `test_no_duplicate_greeting`: verificar que un saludo en medio de conversación NO genera "hola de nuevo"
- `test_no_farewell_in_recommendation`: verificar que una recomendación NO contiene frases de despedida
- `test_no_farewell_in_guidance`: verificar que una guidance NO contiene frases de despedida
- Actualizar `test_smalltalk_prompt_has_no_mid_conversation_farewell`: verificar que el prompt prohíbe despedida fuera de contexto
- Actualizar `test_smalltalk_prompt_no_duplicate_greeting`: verificar que el prompt prohíbe saludo duplicado

**7. Limpieza y creación de documentación (Technical Writer):**
