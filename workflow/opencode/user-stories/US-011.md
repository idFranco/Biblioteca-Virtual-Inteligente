# User Story — US-011 — Sala de lectura con acceso al libro alquilado, chatbot redimensionable y corrección de portadas en blanco

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como usuario, quiero poder alquilar un libro cuando está disponible y acceder a él en una sala de lectura donde pueda leerlo, y además poder agrandar o achicar la ventana del chatbot (actualmente pequeña y fija) seleccionándola, y que todas las imágenes de los libros se rendericen correctamente (algunas quedan en blanco), para tener una experiencia completa de lectura y navegación sin fricciones en la biblioteca virtual.

---

## Functional Description

1. **Alquiler de libro disponible (regresión de US-005):** El flujo de alquiler ya está validado en US-005. El backend ya verifica disponibilidad de forma atómica (`AvailableCopies > 0`) dentro de una transacción y bloquea alquileres duplicados activos (`CreateRentalCommandHandler`). Esta historia solo exige que la UI de catálogo exponga la acción "Alquilar" únicamente para libros disponibles y que el usuario tenga el permiso `rentals.create`.
2. **Sala de lectura:** Un usuario con un alquiler NO devuelto (estado `Active` o `Overdue`) de un libro puede abrir ese libro en una sala de lectura (`/sala-lectura/:bookId`) desde la acción "Leer" en "Mis alquileres". La autorización se valida EN EL BACKEND: el endpoint `GET /api/books/{bookId}/reading` devuelve el detalle del libro y su descripción únicamente si el usuario solicitante posee un alquiler no devuelto para ese libro. El contenido de lectura es la descripción del libro persistida en la base de datos (no se inventa texto completo ni se integra full-text de Open Library en esta historia).
3. **Chatbot redimensionable:** La ventana del chatbot (hoy `fixed w-80` pequeña y fija) debe poder agrandarse y achicarse seleccionándola: botón de colapsar/expandir entre tamaño compacto y grande + asa de redimensionado por arrastre (con mínimos/máximos), persistiendo el tamaño elegido entre navegaciones.
4. **Corrección de portadas en blanco:** Causa raíz detectada: `covers.openlibrary.org` devuelve una imagen placeholder en blanco (no un error HTTP 404) cuando no existe portada, por lo que el `onError` actual no se dispara y la tarjeta queda en blanco. Solución: componente `BookCover` reutilizable que detecta imágenes en blanco (ancho/alto natural < umbral) y cae al `CoverOrnament`, además del `onError` y un skeleton de carga.

    Given un usuario sin permiso books.read

    Given el chatbot expandido
    When el usuario pulsa el botón de colapsar o arrastra el asa
    Then la ventana del chatbot se reduce al tamaño mínimo definido

  Scenario: Persistencia del tamaño
    Given el usuario redimensionó el chatbot
    When navega a otra sección
    Then el tamaño elegido se conserva

Feature: Portadas de libros
  Scenario Outline: Renderizar la portada o su fallback
    Given un libro con <identificador>

    Examples:
      | identificador                       |
      | ISBN con portada real en OL         |
      | ISBN sin portada (placeholder)      |
      | OLID con portada real               |
      | OLID sin portada                    |
      | Libro sin ISBN ni OLID              |

## Technical Plan

### Decisión arquitectónica: contenido y autorización de la sala de lectura

- El contenido de lectura es la `Description` del libro persistida en la base de datos (los 50 libros del seed tienen descripciones). No se integra full-text de Open Library en esta historia (decisión que evita problemas de licencias y sobrecarga).
- La autorización se valida en el backend (regla obligatoria: no confiar en el frontend). Un usuario solo lee un libro si tiene un alquiler con `Status != Returned` (`Active` o `Overdue`) para ese libro.

### Backend (workflow/backend)

1. **Query nuevo** — `src/Application/Queries/Books/GetBookForReadingQuery.cs`
   `public sealed record GetBookForReadingQuery(Guid BookId, Guid UserId) : BaseQuery<BookForReadingResponse>;`
2. **Contrato nuevo** — `src/Application/Contracts/Books/BookContracts.cs`
   Añadir `BookForReadingResponse` (mismos campos que `BookResponse` más `RentedAt`, `DueDate`).
3. **Handler nuevo** — `src/Infrastructure/Handlers/Books/GetBookForReadingQueryHandler.cs`
   `IQueryHandler<GetBookForReadingQuery, BookForReadingResponse>`. Consulta el alquiler NO devuelto del usuario para el libro (join con `Books`) con `ReturnedAt == null` (el estado `Overdue` solo lo asigna el handler de devolución tras una devolución tardía, por lo que la condición correcta es `ReturnedAt == null`, no `Status != Returned`). Si no existe → `throw new KeyNotFoundException(...)` (mapeado a 404 por `GlobalExceptionHandler`). Proyecta a `BookForReadingResponse`.
4. **Endpoint** — `src/WebAPI/Controllers/BooksController.cs`
   `[HttpGet("{bookId:guid}/reading")]` con `[Authorize(Policy = "books.read")]`; despacha `GetBookForReadingQuery(bookId, UserIdFromToken)` vía `IDispatcher` (controller delgado, sin lógica de negocio).
5. **Sin migraciones**: el esquema no cambia.

### Frontend (workflow/frontend)

1. **Tipos** — `src/types/index.ts`: añadir `BookForReading`.
2. **Servicio** — `src/services/books.ts`: método `getBookForReading(bookId)` (GET `/books/{id}/reading`).
3. **Componente `BookCover`** — `src/components/books/BookCover.tsx`:
   - Skeleton de carga mientras carga la imagen.
   - Fallback por `onError`.
   - Detección de imagen en blanco: en `onLoad`, si `naturalWidth < 30 || naturalHeight < 30` → tratar como no disponible → mostrar `CoverOrnament`.
   - Refactor de `BookCard` (y de cualquier tarjeta que pinte portadas) para usar `BookCover`.
4. **Página sala de lectura** — `src/pages/SalaLecturaPage.tsx`: lee `:bookId`, llama a `getBookForReading`, renderiza el libro con la identidad cálida de librería (layout de lectura cómodo: tipografía serif, línea de lectura, portada, fecha límite del alquiler). Maneja 404/denegado y estado de carga.
5. **Ruta** — `src/routes/index.tsx`: `/sala-lectura/:bookId` bajo `Layout` con `PermissionGuard` de `books.read` + `rentals.view_own`.
6. **Acción "Leer"** — `src/pages/MisAlquileresPage.tsx`: enlace a `/sala-lectura/:bookId` para alquileres `Active`/`Overdue`.
7. **Chatbot redimensionable**:
   - `src/stores/chatWidgetStore.ts` (Zustand, nuevo): estado `size` (compact/large), persistido en `localStorage`.
   - `src/components/chat/ChatWidget.tsx`: botón expandir/colapsar, asa de redimensionado por arrastre (mín. `w-72/h-80`, máx. ancho completo en móvil / `w-[28rem]` en escritorio), `aria-label`s, teclado accesible, conserva mensajes al redimensionar.

### Chatbot y MCP

- Sin cambios de grafo, prompts ni MCP. El chatbot ya reutiliza `consultar_libro_en_curso` / `get_estado_lectura` para conocer el estado de lectura del usuario.
