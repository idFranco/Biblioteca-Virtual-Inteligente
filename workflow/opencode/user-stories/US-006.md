# User Story — US-006 — Mitigar riesgos técnicos de US-005 y limpiar la estructura de workflow/opencode

*(Possible statuses: Draft, Planned, Approved, In Progress, Implemented, Validated, Rejected)*

## User Story

Como administrador del proyecto, quiero mitigar los riesgos técnicos registrados en la US-005 (vulnerabilidad NU1903 en SQLitePCLRaw, ausencia de endpoint de gestión de roles, falsos 429 por rate limiting en auth, y uso de sessionStorage para el JWT) y eliminar la carpeta espuria `workflow/opencode/other` con su archivo duplicado, para reducir la deuda técnica y de repositorio antes de avanzar a las siguientes historias.

---

## Functional Description

- **Mitigación NU1903 (HIGH):** `SQLitePCLRaw.lib.e_sqlite3` 2.1.11 se arrastra transitoriamente desde `Microsoft.EntityFrameworkCore.Sqlite` (EF Core 10) y bundle SQLite < 3.50.2 (GHSA-2m69-gcr7-jv3q / CVE-2025-6965). Se pinna el paquete nativo a `2.1.12` (versión parcheada de la misma línea 2.1.x) en `BibliotecaVirtual.Infrastructure.csproj`. Resultado esperado: `dotnet build` sin warning NU1903 y `dotnet list package --vulnerable` en 0.
- **Endpoint de gestión de roles (`roles.manage`):** Hoy la promoción de rol a `Bibliotecario` en pruebas se hace editando la DB directamente (riesgo US-005). Se agrega endpoint `PUT /api/users/{userId:guid}/role` protegido con policy `roles.manage` (solo Admin) que asigna/remueve el rol de un usuario mediante `UserManager`. El permiso `roles.manage` se sembra en el rol `Admin`. El rol asignado queda vigente para los próximos JWTs (re-login requerido para tomar los nuevos claims de permiso — comportamiento existente documentado). No se implementan recargas de claims en vivo por token.
- **Rate limiting auth (R3):** el `PermitLimit = 10/min` provoca falsos 429 durante bates de pruebas (register/login). Se sugiere un `AUTH_RATE_LIMIT_PER_MINUTE` en appsettings/env (default 10 des se mantiene el comportamiento de seguridad; el QA puede ejecutar pruebas espaciadas o subiendo el valor en la env sin tocar código). Documentación del valor en README backend.
- **JWT en sessionStorage (R4):** Constraint académico ya registrado en DECISIONS (ADR-014? — mantener la elección de sessionStorage con mitigación XSS estricta, no `dangerouslySetInnerHTML`, sanitización y limpieza en logout; se documentará como aceptado con mitigación explícita: `SameOrigin` (sin credenciales cross-site), ninguna librería de almacenamiento adicional, y noble en README/flujo de seguridad). No se migra a cookies HttpOnly en esta historia (cambio arquitectónico mayor, fuera de alcance).
- **Limpieza de repositorio:** eliminar el archivo `workflow/opencode/other/feature-US-005-rental-y-devolucion.md` y la carpeta vacía `workflow/opencode/other/`. Verificación: `git ls-tree -r main | grep opencode/other` no devuelve resultados tras el merge.
- **Actualización del Risk Register:** el log de AI engineering actualiza la ficha de riesgos de US-005 indicando el estado de cada riesgo (mitigado/aceptado con mitigación).

## Technical Plan

### 1. Limpieza de repositorio (sin código)
- `git rm --cached workflow/opencode/other/feature-US-005-rental-y-devolucion.md` + borrado del directorio, o simplemente `git rm -r workflow/opencode/other/`.
- Incluir en la rama `feature/US-006-*` (debe estar en la rama que se va a mergear; si el PR-US-005 propaga el archivo, se resolindel también ahí antes del merge de US-006). Validación: `git ls-tree -r origin/main | grep opencode/other` vacío.

### 2. Backend — NU1903
- `workflow/backend/src/Infrastructure/BibliotecaVirtual.Infrastructure.csproj`:
  `<PackageReference Include="SQLitePCLRaw.lib.e_sqlite3" Version="2.1.12" />`
  (Pin directo sobre la dependencia transitiva de `Microsoft.EntityFrameworkCore.Sqlite`; sin cambios de código; la línea 2.1.x mantiene el mismo contrato managed v2.1.x ya usado por el proyecto.)
- Verificar `dotnet build` remueve el aviso NU1903 y `dotnet list package --vulnerable` reporta 0.

### 3. Backend — Endpoint asignación de rol (`roles.manage`)
- `Application/Commands/Roles/AssignUserRoleCommand.cs` (o `Commands/Auth`), `BaseCommand<AssignRolResult>`. `AssignUserRoleCommand(Guid UserId, string RoleName)`.
- Validator FluentValidation: `UserId` no vacío; `RoleName` ∈ {`Admin`,`Bibliotecario`,`Usuario`}.
- Handler `AssignUserRoleCommandHandler` (Infrastructure/Handlers/Roles): UserManager; si rol no existe → `NotFoundException`; remueve roles actuales y agrega el solicitado (`RemoveFromRolesAsync` + `AddToRoleAsync`); si ya lo tenía → `ConflictException` (409); retorna `AssignRoleResult(UserId, RoleName)`.
- `WebAPI/Controllers/UsersController.cs`: `[Authorize(Policy = "roles.manage")]` en `PUT /api/users/{userId:guid}/role`.
- `Program.cs`: `options.AddPolicy("roles.manage", p => policy.RequirenClaim("permission", "roles.manage"));` y en el seed de `rolePermissions["Admin"]` añadir `"roles.manage"`.
- `DependencyInjection.cs`: registrar command+validator (patrón existente).

### 4. Backend — Rate limiting configurable
- `Program.cs`: `builder.Configuration["AUTH_RATE_LIMIT_PER_MINUTE"]` (default `10`) → `PermitLimit`.
- Documentar en README backend: subir durante pruebas QA locales.

### 5. Docs/Risk
- `README backend` sección rate limit + pin.
- Log AI engineering `workflow/opencode/ai-engineering/feature-US-006-*` (ramas `feature/US-006-<name>`) con Risk Register actualizado. No se toca el código del chatbot/MCP.

## Implementation Notes

- **Pin NU1903:** `SQLitePCLRaw.lib.e_sqlite3` pinned a `2.1.12` (patched; `dotnet list package --vulnerable` → 0 vulnerables; `dotnet build` 0 warnings/0 errors).
- **Runtime note (environment):** the patched native lib `libe_sqlite3.so` demands glibc ≥ 2.34; this dev machine (Debian 11) runs glibc 2.31, so local `dotnet run` cannot load it. Per user decision, runtime/QA uses Docker (`dotnet/aspnet:10.0` = glibc ≥ 2.36). Requires `sudo usermod -aG docker $USER` for QA on this host.
- **Endpoint** `PUT /api/users/{id}/role` created (`UsersController.cs`, policy `roles.manage`), seeded into Admin, validator Restricts to `Admin|Bibliotecario|Usuario`, handlers included en DI.
- **Rate limiting** `AUTH_RATE_LIMIT_PER_MINUTE` (default 10) env-configurable in Program.cs.
- `workflow/opencode/other/` directory removed via `git rm -r`.
- Frontend playwright no changes; npm build + lint OK.
